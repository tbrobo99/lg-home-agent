# The app shell

The UI is a single-page app with no framework, no bundler and no `node_modules` in
the repository. It is three files served straight from `app/web/`:

```
app/web/
├── index.html              markup + an inline SVG icon sprite
├── style.css               the whole visual system (~560 lines)
├── app.js                  state, rendering, event delegation (~560 lines)
├── manifest.webmanifest    name, icons, standalone display
├── sw.js                   service worker (shell cached, /api never cached)
├── icon-192.png            generated by tools/icon-source.html
└── icon-512.png            same, at 512 px
```

Everything the page needs is fetched from `/api/*`, so the same files work whether
they are served by `run.py`, a static host, or a WebView.

## Screens

| Screen | What is on it |
|---|---|
| Devices | Room tabs, a temperature / humidity / running summary, the two-column device grid, quick actions, and the next scheduled task |
| Schedule | Every task with its repeat rule and next run, plus per-task delete |
| Assistant | The conversation, suggestion chips, and the composer |

Tapping a device card opens a bottom sheet with the target temperature, the mode
pills and a power button. Tapping the power button on the card itself toggles the
device without opening the sheet.

The quick actions are real commands, not shortcuts: they post a sentence to
`/api/chat`, so they go through the same parser as typed input. "Cool 24°C" sends
`turn on the living room AC and set it to 24 degrees`, and the room tab changes
which room the sentence names.

## Install it on a phone

The page is a valid PWA, so it installs to the home screen with no store, no APK
and no build step.

1. Start the server so the phone can reach it:

   ```bash
   python run.py --lan
   ```

   It prints something like `Phone: http://192.168.1.23:8848`. The laptop and the
   phone must be on the same network.

2. Open that URL on the phone.

   - **Android / Chrome** — menu → *Add to Home screen* → *Install*.
   - **iOS / Safari** — share → *Add to Home Screen*.

3. Launch it from the home screen. It opens full screen, without browser chrome,
   and remembers the shell offline.

There is no authentication. Anyone who can reach the port can control the
appliances, so only run `--lan` on a network you trust.

## Packaging as an Android APK

Capacitor wraps the same files in a WebView. This is optional — the PWA already
installs to the home screen — but it gives you a real APK to hand in, and it lets
the app talk to a fixed address without typing a URL.

```bash
# once, at the repository root
npm init -y
npm i -D @capacitor/cli
npm i @capacitor/core @capacitor/android
npx cap init "Home Agent" com.example.homeagent --web-dir=app/web
npx cap add android
```

Then point the WebView at your always-on host (`capacitor.config.json`):

```json
{
  "appId": "com.example.homeagent",
  "appName": "Home Agent",
  "webDir": "app/web",
  "server": {
    "url": "http://192.168.1.1:8848",
    "cleartext": true
  }
}
```

```bash
npx cap sync android
npx cap open android      # opens Android Studio; Run, or Build > Build APK
```

`server.url` makes the app a thin client for the machine that runs the agent, so
the phone always sees live state and the scheduler keeps running when the phone
is asleep. If you would rather ship the shell inside the APK, drop `server.url`,
set the host at runtime instead, and add a settings field that stores it in
`localStorage`.

Because the host is plain HTTP, Android also needs cleartext traffic allowed —
`cleartext: true` covers the WebView, and `android/app/src/main/AndroidManifest.xml`
needs `android:usesCleartextTraffic="true"` on `<application>` for anything else.

## Regenerating the icons

`tools/icon-source.html` renders the icon at any size. With Edge or Chrome:

```bash
msedge --headless=new --window-size=512,512 \
       --screenshot=app/web/icon-512.png tools/icon-source.html
```

## Why no framework

The whole UI is a render function over one snapshot object, refreshed every four
seconds. At this size a framework would add a build step, a lockfile and a
dependency tree to a project whose selling point is that it runs on a router with
`python3` and nothing else.
